# Iteration 9: Marginalization, Focal Loss, Downsampling & New Features

**Date:** 2026-04-06
**Branch:** `add-multilabel-classification`
**Commits:** `0efe282` through `c4ecc33`

## Overview

Iteration 9 explored five inference and training improvements aimed at closing the remaining accuracy gaps from iteration 8. Work was split into two phases: Phase 1 tested inference-only changes (marginalization, configurable detection threshold) against the iteration 8 model weights; Phase 2 retrained the model with new features, focal loss, and downsampled plain data. Neither phase improved over the iteration 8 baselines, but valuable infrastructure was added for future iterations.

### Changes Introduced

| Change | Phase | Description |
|--------|-------|-------------|
| Sub-type marginalization | 1 | Derive category probabilities by summing sub-type probabilities per category instead of using the dedicated category head |
| Configurable detection threshold | 1 | Expose `detection_threshold` in `model_config.json` (lowered from 0.5 to 0.3) |
| `section_header_ratio` feature | 2 | Ratio of lines matching `[section]` patterns -- discriminates INI from key_value |
| `json_lines_ratio` feature | 2 | Ratio of lines that parse as valid JSON -- discriminates JSONL from code/prose |
| Focal loss (gamma=2.0) | 2 | Downweights easy/common examples during training to improve rare sub-type performance |
| Plain downsampling | 2 | Capped `plain` at 10,000 samples (was 57,260) to reduce category imbalance |
| Backward-compat ONNX loading | 2 | Tier 2 gracefully handles models with fewer features than expected |

## Phase 1: Inference-Only Changes

Phase 1 tested marginalization and detection threshold changes against the iteration 8 ONNX model weights without retraining. Full results are in [Phase 1 eval report](2026-04-06-phase1-marginalization-eval.md).

### Results

| Eval Set | Iter 8 Baseline | Phase 1 (Cat Head) | Phase 1 (Marginalization) |
|----------|-----------------|-------------------|--------------------------|
| Clear (4,071 samples) | **93.4%** | 88.1% | 86.9% |
| Boundary (3,156 samples) | **59.6%** | 60.2% | 41.0% |

### Key Finding

Marginalization **regressed** accuracy on both eval sets. The sub-type head was trained to distinguish 30 sub-types, not to produce well-calibrated per-category probability sums. Probability dispersion across many sub-types causes structured samples to be misclassified as prose -- 296 structured samples were predicted as prose under marginalization, with JSONL (126) and pipe_table (103) as the worst offenders.

The detection threshold change (0.5 to 0.3) could not be evaluated because the iteration 8 model config lacks a `detection_map`.

- **Structured to code errors also increased** (62 to 116).

## Root Cause Analysis

### 1. Python/Rust Featurizer Gap (~5.7pp)

The iteration 8 baseline of 93.4% was measured using the Rust ONNX integration. Both Phase 1 and Phase 2 evals used the Python featurizer (`eval_onnx`). The 5.7pp gap between the Python category-head eval (87.7%) and iteration 8 Rust eval (93.4%) indicates the two feature extractors produce different values for the same input text. This is the single largest source of apparent regression and must be resolved before training improvements can be accurately measured.

### 2. Downsampling Plain Hurt Boundary Performance

Reducing plain from 57K to 10K samples likely removed many boundary-adjacent examples. The boundary eval dropped from 60.2% to 40.7% after retraining, a 19.5pp regression. Future downsampling should use boundary-aware stratification to preserve hard examples.

### 3. JSONL and Pipe Table Remain Intractable with Current Features

JSONL (4.5%) and pipe_table (6.0%) are effectively unclassifiable with structural features alone. JSONL content contains the same characters as JSON/JavaScript (braces, quotes, colons), and pipe tables share characters with code and prose. These sub-types need content-aware features or specialized detection.

### 4. Focal Loss Effect Inconclusive

With gamma=2.0, the model achieved strong validation metrics (94.9% category accuracy) but eval accuracy did not improve. The benefit of focal loss is masked by the featurizer gap and eval pipeline differences.

## Infrastructure Gains

Despite the accuracy regression, iteration 9 delivered durable infrastructure improvements:

1. **Configurable detection threshold** -- `model_config.json` now supports `detection_threshold`, enabling threshold tuning without code changes.
2. **Focal loss support** -- Training pipeline supports focal loss with configurable gamma, ready for future experiments.
3. **Per-sub-type downsampling** -- `split_dataset` supports `--max-per-sub-type` for controlled class balancing.
4. **Two new discriminative features** -- `section_header_ratio` and `json_lines_ratio` are computed and available for future models.
5. **Backward-compatible ONNX loading** -- Tier 2 gracefully handles models with fewer features than the current feature extractor produces, enabling incremental feature additions.

## Lessons Learned

1. **Eval pipeline parity is prerequisite to training experiments.** The Python/Rust featurizer gap made it impossible to distinguish training improvements from eval artifacts. All future iterations must first ensure feature extraction parity.
2. **Marginalization requires training-time support.** Deriving category from sub-type probabilities post-hoc does not work when the sub-type head was not trained with marginalization in mind.
3. **Aggressive downsampling needs stratification.** Capping plain at 10K without preserving boundary-adjacent examples caused a severe regression on boundary eval.
4. **Infrastructure changes and accuracy changes should be evaluated separately.** Bundling five changes into one iteration made it difficult to attribute improvements or regressions to specific changes.
