# Iteration 5: Label Cleanup + 10 New Features

**Date:** 2026-04-04
**Clear eval accuracy:** 93.2% (271 errors / 3,998 samples)
**Boundary eval accuracy:** 85.3%
**Validation accuracy:** 96.0%
**Features:** 38 (28 original + 10 new)

## What Changed

### 1. Three-way label audit (Magika + GPT-5.4-mini)

Ran Google Magika on all training (136K) and eval (10K) samples as an independent
content-type oracle. Where Magika disagreed with the current label, sent to
GPT-5.4-mini for a second opinion. Only corrected when both oracles agreed.

- **Eval clear:** 234 category corrections, 998 ghost sub-type remaps
- **Eval boundary:** 1,248 category corrections
- **Training:** 10,384 category corrections, 34,504 ghost sub-type remaps

### 2. Ghost sub-type removal

Remapped `pdf_dump`, `ocr_garbage`, `boilerplate`, `skip` sub-types to real
`ContentSubType` values using Magika. These ghost sub-types existed in training
data but not in the Rust enum — the model was learning categories it could never
output.

### 3. Category/sub-type consistency enforcement

Enforced the rule: sub_type determines category. If `sub_type=plain` then
`category=prose`, if `sub_type=json` then `category=structured`, etc. Fixed
7,802 contradictions in training and 464 in eval.

### 4. Literal `\n` normalization

Added `text.replace("\\n", "\n")` before feature extraction in both Python
and Rust. Text arriving from JSON/CSV payloads sometimes has literal backslash-n
instead of real newlines, breaking all line-based features.

### 5. Ten new features (28 → 38)

| Feature | Signal | Primary target |
|---------|--------|----------------|
| `avg_words_per_line` | Prose=20+, code=3-8, structured=2-10 | All confusions |
| `operator_density` | `==`, `!=`, `&&` per 1000 chars | prose→code |
| `inline_markup_count` | `**bold**`, `` `code` ``, `[link](url)` per 1000 chars | prose→code |
| `indentation_consistency` | Regular indent levels (multiples of 2/4) | code detection |
| `markup_heading_ratio` | `# Heading` and RST underlines | prose→code (RST/MD) |
| `code_fence_density` | Lines inside ` ``` ` blocks | prose→code |
| `prose_paragraph_ratio` | 3+ consecutive long lines without structure | structured↔prose |
| `semicolon_line_ending_ratio` | Lines ending with `;` | code detection |
| `list_item_ratio` | `- item`, `1. item` patterns | prose detection |
| `parenthesis_density` | `()` per 1000 chars | code detection |

## Iteration 6 Plan

### Phase 1: Manual label audit of remaining 271 errors
Run `audit_model_errors.py` to get LLM opinion on each error. Where LLM agrees
with model (FIX_LABEL), correct the label. Apply to both training and eval.

```bash
source ~/.a.sh
uv run training/audit_model_errors.py \
    --predictions training/output/eval_predictions.clear_v2.jsonl \
    --output training/output/model_error_votes.jsonl \
    --backend openrouter --model openai/gpt-5.4-mini --concurrency 20
```

Then apply:
```bash
uv run training/apply_corrections.py \
    --votes training/output/model_error_votes.jsonl \
    --input training/data/eval/clear_v2.jsonl \
    --output training/data/eval/clear_v3.jsonl \
    --no-remap-subtypes
```

Also run on training data — same pattern exists there:
```bash
# First: generate predictions on training data to find model errors
# Then: audit those with LLM and apply corrections
```

- Add BatchNorm before activations
- Widen first layer: 128 → 256
- Increase sub-type loss weight 0.3 → 0.5

### Phase 3: Evaluate and iterate
- Retrain on corrected data
