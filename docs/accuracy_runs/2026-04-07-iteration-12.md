### Phase 1: JSONL Fix (Tasks 9, 11)

#### Root Cause Discovery

Fresh baseline (93.5%) revealed JSONL was 145 of 263 errors (55%). Feature analysis showed:

- `json_lines_ratio` = 0.019 for failing JSONL samples (should be ~1.0)
- `json_lines_ratio` = 0.186 for passing JSONL samples
- **Root cause:** `_normalize_escaped_newlines()` runs before feature extraction and converts literal `\n` inside JSON string values to real newlines, breaking JSONL line structure
- 80% of JSONL eval samples were destroyed by this normalization

Example: `{"text": "hello\nworld"}` becomes two lines after normalization, so `json_lines_ratio` (which checks `startswith('{') and endswith('}')` per line) computes near-zero.

#### Fix

Compute `json_lines_ratio` on raw text BEFORE newline normalization. All other features still use normalized text.

```python
# Before (broken):
sample = _normalize_escaped_newlines(text[:SAMPLE_SIZE])
return {name: fn(sample) for name, fn in FEATURES.items()}

# After (fixed):
raw_sample = text[:SAMPLE_SIZE]
sample = _normalize_escaped_newlines(raw_sample)
result = {}
for name, fn in FEATURES.items():
    result[name] = fn(raw_sample) if name == "json_lines_ratio" else fn(sample)
return result
```

## Key Learnings

1. **Measurement before optimization:** The 93.0% from iteration 11 and the stale 87.7% slice report were misleading. The true baseline (93.5%) was only known after running a fresh eval with manifested artifacts.

2. **One variable per experiment works:** The feature bug fix alone moved accuracy +2.9pp. The JSONL data augmentation without the fix only moved it -0.5pp (regression). Isolating variables revealed the real cause.

3. **Feature bugs > data quantity:** 1,845 new JSONL samples didn't help when the discriminative feature was broken. Fixing the feature alone would have been sufficient.

4. **pipe_table was a red herring:** The stale 87.7% model showed 101 pipe_table errors. The fresh 93.5% model had only 3. Diagnosis must use current data.
