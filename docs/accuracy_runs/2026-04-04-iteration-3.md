## What Changed in This Iteration

### 1. Taxonomy reclassification: YAML/TOML/INI → structured

Moved YAML, TOML, and INI sub-types from `code` to `structured` category in both Rust types and training pipeline. Rationale: these are data serialization formats (key-value/hierarchical data), not programming languages. Matches industry convention (GitHub Linguist "data" category, Apache Tika).

**Impact — massive accuracy gains for config formats:**

| Sub-type | Iteration 2 | This run | Delta |
| --- | ---: | ---: | ---: |
| `yaml` | 50.4% | 91.2% | **+40.8 pts** |
| `toml` | 79.8% | 99.0% | **+19.2 pts** |
| `ini` | 72.4% | 89.8% | **+17.4 pts** |

### 2. Rust feature parity (18 → 28 features)

Implemented 10 features in `src/features.rs` that were already computed by the Python training pipeline but missing from Rust inference:

- `hyphenated_line_break_ratio`, `short_repeated_line_ratio`, `page_number_density` — PDF/artifact detection
- `label_value_line_ratio`, `table_fragment_score`, `uppercase_header_ratio` — extraction artifact signals
- `dictionary_word_ratio`, `encoding_error_ratio` — prose/artifact distinction
- `repeated_ngram_ratio`, `sentence_coherence_score` — text quality signals

For `dictionary_word_ratio`: embedded a 227K-word English wordlist via `include_bytes!`.

Previously, these 10 features were zero-filled at inference, producing spurious values after z-score normalization. Now inference matches training exactly.

### 3. GPU-accelerated training

Added `--device auto|cpu|cuda` flag to `train.py`. Training ran on RTX 5070 Ti (CUDA 13.0). Early stopping triggered at epoch 145 (best at epoch 130).

### 4. Frozen eval sets (versioned)

Eval sets frozen in `eval/v1/clear.jsonl` and `eval/v1/boundary.jsonl` with symlinks from `eval/`. Labels updated for taxonomy change. Pipeline `train:split` now skips eval generation when frozen sets exist.

## Dominant Remaining Failure Mode: Artifact Under-detection

Almost all remaining errors are artifact samples misclassified as prose, structured, or code:

- **artifact → structured** (129 total): PDF dumps with tabular remnants, boilerplate with structured patterns, skip with structured patterns
- **artifact → prose** (85 total): OCR garbage with enough real words, boilerplate license text
- **artifact → code** (46 total): Boilerplate from code repos with code-like patterns

The code↔structured confusion from iteration 2 (111 errors) has been **eliminated** — code→structured dropped to just 15 errors.

## Phase 2 Assessment

**Current: 89.1%. Target: 97%. Gap: 7.9 points (~316 samples).**

The remaining errors are concentrated in artifact sub-types. Phase 2 should focus on:

1. **Tier 1 rules for artifact detection** — `encoding_error_ratio`, `dictionary_word_ratio`, `page_number_density` features are now available. Short-circuit rules can catch obvious OCR garbage and PDF dumps before they reach the model.
2. **Model architecture upgrade** — wider layers may help the model learn the artifact→structured/prose boundary better.
3. **Hard negative mining** — training with artifact samples that look like prose/structured to improve the decision boundary.
